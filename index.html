Spec-style concept project

Keep depth semantic in HTML. Let spatial runtimes decide how much of it becomes visible.

depth-sol complements aframe-bootstrap instead of competing with it. In a normal browser, depth behaves like browser-safe spatial metadata shaped by a document light source called sol. In a VR-capable runtime, the same values can translate into true volume and light placement.

A-Frame review

What stays in aframe-bootstrap

Native spatial UI primitives, tokens, interaction rules, and real scene composition remain the job of the A-Frame library.

Why this complements A-Frame

Bridge spec

One authoring contract, two render paths.

The companion layer becomes useful when it can actually translate. This bridge treats the authored page as the source of truth, then emits either a flat-browser shadow model or a scene-native A-Frame interpretation from the same semantic inputs.

Reference archive

Depth cues now split cleanly between browser illusion and real spatial rendering.

The current synthesis is simple: shadows and lighting belong to the browser fallback, while true volume belongs to spatial runtimes like A-Frame, WebGL, or WebXR. That separation keeps this project aligned with the direction already being established next door.

Use shadow as fallback, not fake geometry everywhere
Keep light direction explicit
Let semantics survive across 2D and XR
Reserve real extrusion for spatial runtimes
